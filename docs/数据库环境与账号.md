# 数据库环境与账号

2026-11-15，按用户授权在 `192.168.2.12:13432` 的 PostgreSQL 18.7 创建两个新数据库。`homelab` 保留；不再作为网关本地开发默认库。创建前确认所有目标名称均未被占用。

## 环境清单

| 用途 | 数据库 | 运行账号 | 迁移账号（库所有者） |
| --- | --- | --- | --- |
| 正式 | ai_gateway | gateway_app | gateway_migrator |
| 测试/当前本地开发 | ai_gateway_test | gateway_test_app | gateway_test_migrator |

两个库均为 UTF8、数据库默认时区 UTC、业务 schema 为 public，从 template0 创建。尚未执行业务 Alembic 迁移，没有业务表。它们共享同一个 PostgreSQL 实例，因此性能测试仍会竞争 CPU、IO 和连接资源，不构成物理资源隔离。

四个账号使用各自独立的 `secrets.token_urlsafe(32)` 随机密码，含 32 字节随机熵、编码后 43 字符。数据库保存 SCRAM-SHA-256 verifier；初始化脚本不在 SQL 中发送明文密码，终端和报告也不输出密码。

## 配置位置

实际用户名、密码、完整 URL 均保存在项目根目录 `.env` 中，权限 0600，已被 `.gitignore` 排除。可在本地编辑器查看；本文件和 `.env.example` 不保存密码。

| 本地配置项 | 当前指向 | 用途 |
| --- | --- | --- |
| DATABASE_URL | ai_gateway_test / gateway_test_app | 当前开发运行默认连接 |
| MIGRATION_DATABASE_URL | ai_gateway_test / gateway_test_migrator | 当前开发迁移连接 |
| TEST_DATABASE_URL | ai_gateway_test / gateway_test_app | 后续测试夹具显式连接 |
| TEST_MIGRATION_DATABASE_URL | ai_gateway_test / gateway_test_migrator | 测试建表/迁移/清理 |
| PRODUCTION_DATABASE_URL | ai_gateway / gateway_app | 正式部署时映射到 DATABASE_URL |
| PRODUCTION_MIGRATION_DATABASE_URL | ai_gateway / gateway_migrator | 正式迁移时映射到 MIGRATION_DATABASE_URL |

MIGRATION/TEST/PRODUCTION 前缀变量是工程准备与部署输入，未增加到设计书 80 项运行配置中。应用、Alembic 和测试夹具尚待 P1 实现，当前仅准备配置，并不表示读取这些变量的业务代码已存在。正式服务只加载所需运行凭证；迁移任务单独加载迁移凭证，不将整份开发 `.env` 作为正式服务的配置包。

原 `postgres` 管理连接仅保存在 `.env.db-admin`（0600），用于后续数据库管理，不供网关应用读取。初始化前 `.env` 备份及恢复凭证位于 `.tools/database-provisioning-20261115/`，同样限制权限且不入库；不得把该目录作为无审查的交付附件。

## 权限与验证

- 四个角色均为 LOGIN、NOSUPERUSER、NOCREATEDB、NOCREATEROLE、NOREPLICATION、NOBYPASSRLS、NOINHERIT；没有互相授予角色成员关系。
- 每库撤销 PUBLIC 的数据库权限以及 public schema 权限；运行账号仅可 CONNECT、使用 public schema，默认获得本环境迁移账号未来创建表的 SELECT/INSERT/UPDATE/DELETE 和序列的 USAGE/SELECT。
- 运行账号不能创建/删除表、TRUNCATE、创建临时表；迁移账号拥有本库并负责 DDL。迁移必须使用对应迁移账号，不能用 postgres 建表后假定默认授权会自动套用。
- 已在两个新库分别用迁移账号创建一次性验证表，用运行账号验证 INSERT/SELECT/UPDATE/DELETE 和序列生成，再验证上述 DDL 被拒绝；验证表已由迁移账号删除。
- 已用真实连接验证四种跨环境连接全部被拒绝：正式运行/迁移账号不能连接测试库，测试运行/迁移账号不能连接正式库。
- 这些限制针对本次新建的两个库。没有更改集群内其他数据库的 PUBLIC 策略，也不声称对其他所有数据库都禁止建立连接。

未来表授权来自迁移角色的默认权限，作用于该角色新建的对象；它不会回填其他角色创建的对象。P1 迁移需单独撤销运行账号对 `alembic_version` 的写权限，避免元数据落入普通业务 DML 授权；测试 fixture 必须检查实际库名是 ai_gateway_test，方可执行重建/清理。默认权限行为依据 [PostgreSQL 18 文档](https://www.postgresql.org/docs/18/sql-alterdefaultprivileges.html)。

## 连接额度

每个运行角色 CONNECTION LIMIT=36，每个迁移角色=2，每库 CONNECTION LIMIT=40。对应当前单实例连接池上限 16+20=36；两套环境的四个角色名义上限合计 76，数据库上限合计 80，服务器 max_connections=100。检查时客户端连接快照为 1（含检查本身）。

以上为已配置的资源上限，不是性能承诺；数据库级额度也不等于强制预留连接。P0 容量冻结仍需结合其他应用占用和运维保留量确认；不得在同一运行角色下额外启动多个网关实例，或把并行测试进程数量无限增加。

## 复核与初始化工具

脱敏实测结果见 [初始化记录](./P0-数据库初始化记录-20261115.json)。可以使用当前测试运行账号进行只读复核：

```bash
.venv/bin/python scripts/p0_preflight.py database --output .tools/p0-test-db-YYYYMMDDTHHMMSSZ.json
```

一次性初始化工具为 `scripts/provision_databases.py`；默认只检查，`--apply` 才创建。遇到任何同名库/角色会拒绝执行，不接管、重置密码或删除已有资源。现已创建完毕，重复运行会因名称冲突退出。若以后需要轮换密码、扩容或重建测试库，另行执行明确的管理操作，不能用重新运行初始化代替。

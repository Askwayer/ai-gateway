## 首次审查修复与复验（历史）

当时完成以下五项修复；后续复核发现关闭路径仍有两项遗漏，现由下一节收口。未增加配置字段或业务范围：

1. raw迭代适配器延后HTTPX在EOF处的自动关闭，finish内关闭与结算共享截止时间；该次MockTransport测试通过，但没有覆盖httpcore读异常内部关闭，也不能证明真实连接池资源释放。已读到的有效usage不因关闭失败而丢失。
2. 入站必须为单一、语法有效的 `application/json`；若带charset，仅允许单一UTF-8声明。正文严格按UTF-8解析，拒绝UTF-16、NaN、Infinity和非有限浮点数；这些请求在登记及转发前返回400。
3. 上游成功响应执行相同的媒体类型与UTF-8 JSON约束；缺失/重复/畸形Content-Type或非UTF-8 charset按502协议错误结算。
4. 网关504保持 `timeout_error`；上游错误的 `Retry-After` 只允许单一、0～3600的整数秒值，拒绝日期、重复头及越界值。
5. 空usage或仅包含未知字段的usage归为missing，全部Token保持NULL；至少一个有效Token字段才归为partial，非法字段仍归为invalid。

上游请求补齐网关生成的 `X-Request-ID`、`X-Gateway-Request-Source: business` 和 `Accept: application/json`。忽略调用者伪造的标识/来源头；上游返回的请求标识另存 `upstream_request_id`。测试核对出站ID、响应ID与已提交登记记录一致。

新增35项故障回归，覆盖读超时/总超时后关闭卡住、成功读完后关闭卡住或抛错、请求取消后关闭卡住、关闭及结算同时卡住，以及协议、Retry-After和usage边界。关闭夹具包含内部AnyIO取消屏蔽，仍须在预算内结束；结算持续失败时保留started并累计失败计数，不能伪称成功，但三层名额仍归零。回归JUnit证据：`.tools/p1-slice-review-regressions-20261115.xml`。

## 两项P1关闭问题修复（当前）

- `app/upstream_transport.py` 将物理关闭放在httpcore网络流适配层处理。HTTPcore读超时/总超时/取消、响应头错误或协议拒绝触发关闭时，底层直接调用asyncio Transport.abort，避免等待会卡住的异步aclose/TLS close_notify。此调用不包含await；httpcore随后自行完成池内请求移除和关闭连接剔除。无需私自删除池列表、重置共享客户端或遗留后台关闭任务。
- Response层EOF延后关闭与finish结算预算仍保留。正常keep-alive不调用物理关闭；故障只中止对应连接，不影响另一条在途请求。即使结算持续超时，也保留started及失败计数，名额和HTTP池资源仍释放；不能把结算失败写成成功。
- HTTPX `_pool`、httpcore AnyIOStream及AnyIO asyncio SocketStream `_transport` 是集中封装的版本适配边界；当前锁定版本为HTTPX 0.28.1/httpcore 1.0.9/AnyIO 4.16.0，升级须运行真实栈与TCP/TLS回环测试。启动命令显式使用asyncio；不增加运行配置，不扩展代理/HTTP2支持。

新增16项回归：9个真实HTTPX/httpcore池故障场景（读超时、总超时、等待响应头超时/取消、读体取消、协议拒绝、读错误、截断响应、成功响应要求关闭）；2个真实本机TCP/TLS默认后端场景；2个TLS握手错误/取消场景；1个结算持续超时场景；1个故障连接与另一在途请求隔离场景；1个池内排队取消场景。故障替身的异步aclose会永久等待，新实现通过直接abort避免进入它，不以吞掉超时或清空整个池通过测试。

单物理连接槽回归核对：底层abort恰好一次、故障池请求项/连接数归零、记录终态和三层名额；随后连续两次200并复用健康连接。结算失败轮次核对started、失败计数、HTTP资源释放和DB恢复后的新请求成功。TCP/TLS回环还等待对端EOF/复位，证明实际socket处置，不仅是关闭协程结束。应用入口仍为ASGI测试入口，不声称覆盖真实客户端断开监督器。

池内排队取消已固定为回归：使用单物理连接槽，先确认两个请求均已登记且第二个确实处于pool queued状态，再取消等待者；断言取消继续传播、等待者结算为client_cancelled、连接持有者仍为started且不被abort。释放持有者后，其请求及后续复用请求均200，所有名额和池请求项归零，关闭客户端时物理连接仅abort一次。

当前证据：`.tools/p1-transport-regressions-20261115.xml`（16项）和更新后的`.tools/p1-slice-quality-20261115.log`、`.tools/p1-slice-summary-20261115.json`。完整质量检查为196项pytest、Ruff、mypy、14组文档测试、执行计划与P0配置候选校验。传输回归仅访问本机临时监听器；本轮没有数据库连接/迁移、未重调DeepSeek。run01～run03保留为修复前的真实DB/上游历史证据，不表述为本轮真实DB端到端结果。
